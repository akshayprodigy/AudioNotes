## F26 - call interruptions

- **Recording.** `RecordingService.registerAudioWatchers`: when `isClientSilenced` changes, `gaps.onSilenced(now, CaptureController.capturedMs)`
  (captured-audio ms, pauses excluded - the cap's clock). `GapTracker` (in `GapPolicy.kt`, synchronized) closes an interval when it turns
  off; `finish(endMs)` closes an open one at the recording's end. A fresh tracker per `startCapture`. In `onDestroy`, once, after `markCaptured`:
  `GapPolicy.toStore(existing, gaps.finish(durationMs), durationMs)` is written with new `AudioDb.setSetting` to
  `capture_gaps:<meetingId>` as `[[startMs,endMs],…]` (normalised); nothing is written when there is nothing to say. An earlier run's stored
  intervals (service redelivered after a kill) are joined, not overwritten. No schema change.
- **Pure policy.** `GapPolicy` (Kotlin): `normalise` (merge overlapping/touching, drop under 2,000 ms after the merge, clamp to [0, length]),
  `totalMs`, `toJson`/`fromJson` (lenient), `toStore`, `sentence(totalMs)`. `GapPolicyTest` (27). Commit `a426087`.
- **Sentence.** "Your phone's microphone was silenced for 4 min (a call, or another app) - that part wasn't recorded." (an em dash in
  the real string). Under a minute: "45 seconds" / "1 second"; from a minute: whole minutes, rounded ("1 min", "2 min" at 90 s); null under a second.
- **Exposed to JS.** No bridge method needed: the existing `db.getSetting('capture_gaps:<id>')` reads it. New `src/capture/gaps.ts`
  (`gapsKey`, `parseGaps`, `normaliseGaps`, `totalSilencedMs`, `gapSentence`, `captureGapNote(raw, recordingMs)`,
  `loadCaptureGapNote(id, recordingMs, getSetting)`) with `src/capture/__tests__/gaps.test.ts` (20). Commit `95ee077`.
  `MeetingScreen.tsx` and `src/screens/meeting/**` were not touched.
- **Mutants (all killed, restored).** Kotlin: touching intervals not merged (2); contained interval's end not kept (1); merge removed (6);
  floor `>=` to `>` (1); floor removed (4); clamp to the end removed (5); clamp to zero removed (1); plural always (1); singular always (2);
  minutes floored not rounded (1); tracker restarts on a repeated "silenced" (1). TypeScript: touching (2), no max (1), floor `>` (1),
  no floor (4), no end clamp (3), plural always (1), singular always (1), minutes floored (1).
- **Device-only / limits.** `isClientSilenced` exists on Android 10+ only, so older phones record no gaps. Whether a real phone call fires
  `onRecordingConfigChanged` with the client silenced, how soon, and whether the interval's start matches the silent stretch in the file
  (the callback thread reads `capturedMs`, which advances per ~128 ms buffer) is unproven. The tracker lives in memory until the end of the
  capture, so a process death loses the intervals noted by that run (the file keeps the silence). The TS and Kotlin twins duplicate the
  merge/floor/clamp/wording rules; each pins the same examples, so a change needs both.

### The one-line hook for Workstream D (`MeetingScreen.tsx`, do NOT paste into `meetingNotes.ts`)
Where the ending/announcement lines are built (the meeting row's length is `meeting.durationMs`):

```ts
import { loadCaptureGapNote } from '../capture/gaps';
// in the effect that loads the meeting's notes:
loadCaptureGapNote(meeting.id, meeting.durationMs ?? 0, db.getSetting).then(setGapNote);
// render next to endingNote / announceLine:
{gapNote ? <Text style={styles.endingNote}>{gapNote}</Text> : null}
```
(`loadCaptureGapNote` never throws and resolves null when there is no key, an empty list, or only flickers; reuse whatever style the
`endingNote` line uses.)
