## F14 — the design decision, and why

**Question (answered by reading, not assumed): do rule-extracted items carry `owner_json`?** No. The rule pass
(`Minutes.extractItems` → `Reconciler` → `AudioDb.replaceItems`) writes `owner_json = NULL`; only the Pro
classifier writes it (`ItemClassifier.run`, `kind:'speaker', id = source line's speaker`). The reader in
`AudioDb.items()` also hid the column unless `item_type` was set, so even a stored owner would have been dropped
on the next reprocess.

**Decision: record the speaker in `owner_json` from Kotlin, not from the C++ extractor.** The first-person branch of
`detectOwner` writes the *speaker's own display name* as the owner token, and the item's source line is known
(`item_sources.utterance_id` → `utterances.speaker_id`). So at the moment of extraction "owner token equals the
source line's speaker's name" is exactly "the owner is that speaker"; a named person ("Maya will ...") writes a
different token. That needs no change to `cpp/minutes`, to the TS twin, or to any golden (`git diff cpp/tests/golden`
is empty), and `Reconciler`/`ItemKey` are untouched: a matched row keeps its old `record`, a fresh row gets an
owner-only record, a hand-typed or retained row is never given one.

* New rule items: `AudioDb.replaceItems` writes `{kind:'speaker', id}` for an extracted action whose owner is its
  source speaker (`ItemOwner.ruleSpeakerJson`).
* Items that predate this build: `AudioDb.adoptRuleOwners` applies the same test **immediately before a rename**
  (inside `AudioDb.renameSpeaker`, and before `answerSuggestion` names a speaker from a remembered voice) — the old
  name in the text is the only evidence and the rename destroys it. Idempotent; skips rows that already have an
  owner, hand-typed rows and rejected rows.
* `StoredItem.record` now exists when `owner_json` alone is set; `StoredItem.classified` (= `item_type != null`)
  is what the classifier's pending test and the review queue mean by "read by the model". Without that split an
  owner-only record would have made the classifier skip every rule item.
* Stored text is never rewritten. One pure resolver, `ItemOwner.resolve` (Kotlin) / `resolveOwnerText`
  (`src/pipeline/itemOwner.ts`), puts the speaker's **current** name into the text at read time. Only
  `kind:'speaker'` resolves; a person record, `unassigned`, a missing speaker or a blank name leaves the text alone.
  The Review queue's `ownerLabel` moved into the same module.
* A hand correction: the editor now opens on the resolved text, and `db.reconcileItemOwner` (called after a save of an
  `item` correction) drops the speaker link when the person typed a different owner, so live resolution can never
  overwrite their words. It never touches `review`.

## F17

1. **Item cites resolve to the transcript line.** `Asker.passages` takes an `itemMoment` lookup
   (`AudioDb.itemMoment`: first source's utterance → speaker; the item's `anchor_start_ms`; null for a hand-typed
   row). An item passage is labelled with that line's speaker and moment and is `anchored`. Summary, minutes
   passage, title and typed row are "Minutes" and **not anchored**.
2. **Unanchored cites are dropped.** `Asker.withoutUnresolvableCites` removes `[n]` of an unanchored passage from the
   raw answer before `nativeValidateAnswer`; an answer left with no cite is the existing "nothing" state, and the
   nothing-state pointers are now `closestResolvable` (closest anchored passages, up to three). The retrieval pool
   (8 fused hits) and the grammar are unchanged. An older stored answer's `Minutes` cite is hidden by `momentsOf`.
3. **Per-sentence cite rule** in `validateAnswer` (`cpp/minutes/ask.cpp`), post-hoc: split into sentences (`.!?` +
   whitespace, newline; `Mr.`/`Dr.`/decimals do not split; a cite written after the full stop belongs to the
   sentence before it — the grammar puts every cite last), drop sentences with no valid `[n]`, rebuild the cite list
   from what survived in first-mention order, keep the refusal-phrase rule. No TS twin exists (`grep validateAnswer
   src` empty), so none was mirrored.
4. **Ask plays.** `Meeting` route gets `play?: boolean`; `AskScreen`, thread rows and worklist rows navigate with
   `{tab:'transcript', atMs, play:true}`; `MeetingScreen` plays once when the recording has audio. A search hit still
   sends `atMs` alone and only scrolls. A row with no moment (typed) opens as before. `atMs = 0` counts as a moment.
   Native `threadJson` now returns `anchorStartMs` (null for typed rows).
