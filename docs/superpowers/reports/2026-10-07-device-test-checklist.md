## 2. Run the instrumented tests

- [ ] **T1 Whole suite on one phone:** `ANDROID_SERIAL=<serial> npm run test:device` (= `scripts/device-verify.sh`). It builds `:app:assembleDebug` + `assembleDebugAndroidTest`, force-stops the app, `adb install -r` both APKs (keeps data), then one `am instrument` per class. `ANDROID_SERIAL` is read by `adb` itself: the script calls bare `adb`, so with two devices attached it dies "more than one device" unless the serial is set. → each class prints `OK (N tests)`, the run ends "passed", `/tmp/instr-run.out` holds everything. Finish onboarding (models downloaded) first: a class where every test skips fails the run on purpose ("verified NOTHING"). [scripts/device-verify.sh]
- [ ] **T2 One class:** `scripts/device-verify.sh Threads` (substring of a name **in the script's list**; no match exits 1 "nothing ran"). → `OK (n tests)`.
- [ ] **T3 (fixed after this list was written: both classes are now in `CLASSES`, so T1 runs them; the direct commands below still work for one class):** the two October classes were not in the script's list (`CLASSES` in `scripts/device-verify.sh`), so T1 never runs them, and `device-verify.sh Corrections` exits 1. After T1 (or any run that installed both APKs) run them by hand:
  `adb -s <serial> shell am instrument -w -r -e class com.innocorelabs.verbale.SpeakerRenameDbTest com.innocorelabs.verbale.test/androidx.test.runner.AndroidJUnitRunner` → **OK (4 tests)**: record, rename, reindex, adopt-before-rename, named person untouched.
