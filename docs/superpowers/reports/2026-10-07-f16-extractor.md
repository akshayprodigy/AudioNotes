## Rules as implemented (engineering decisions — founder to review)

**(a) "let's start" is meeting flow.** A sentence whose only action cue is
`let's start | begin | get started | kick off` is not an action, unless the same sentence has a time
marker: any `DUE` match, or `tomorrow`, `next <word>`, `on <weekday>`, `by <word>`, `after <word>`
(`FLOW_TIME`). The flow phrase is replaced by a placeholder and the remainder re-judged, so
"Let's start, and I'll send the notes." and "Let's start the call, please share your screen." stay
actions (a second cue). Consequences to be aware of:
- `today` is a `DUE` match, so "Let's get started today." stays an action (as the brief specified).
- `by <word>` is broad: "Let's start the meeting by introducing everyone." stays an action.
- A surviving "let's start ... on Monday" action is still owned by the speaker (`let's` is still in
  `ACTION_FIRST_PERSON` for owner detection).

**(b) `<Name> will <verb>` for any verb.** Name = a capitalised word of 2-21 letters directly before
`will` that is not in a non-name list (`I We You The This That It Let Please He She They There These
Those Here Who What Which And But So Then If When`). After `will`, hedges
(`probably, definitely, also, just, still, maybe, likely, ...`) are skipped; then:
- `be / been / being / not / never` -> not an action; a clause that ends at `will` (no verb) -> not an action;
- otherwise an action if the sentence has a `DUE` match OR there are at least two words after the verb.
The closed verb list in `ACTION_OBLIGATION` is untouched and remains the fast path.
Decisions beyond the brief:
- `never` is treated like `not` (the brief listed `not/won't`; "Priya will never agree to that" is not a commitment).
  `won't` needs no handling: it contains no `will`.
- Pronouns (`He/She/They/...`) do not count as a Name for the open rule. `detectOwner` is unchanged, so the
  closed-list "She will send ..." still reports owner "She" (pre-existing quirk, out of scope).
- `will have been ...` is not excluded (the brief names only be/been/being).
- **Required by the brief's negative case but outside "Name will":** "We will not ship Friday." was an action
  through `ACTION_FIRST_PERSON` (`we will`). Added `NEGATED_FIRST_WILL` (`i|we will [hedges] not|never`),
  neutralised before the cue test. "We will be late" is still an action (not touched).

**(c) `before <day>` is a due.** `DUE` gains `before (the)? (end of day|week|month | eod | cob | noon | today |
tomorrow | next <week|month|weekday> | <weekday> | <day> <month>)`. The matched text keeps "before", so an
action reads "(due before Wednesday)". dateNorm: `before` is deliberately NOT in `DROPPED_LEADS`, so
"before Wednesday" stays unresolved (null) and the review queue's "date could not be pinned to a day" cue
applies. This was already the behaviour in TS and in `DateNorm.kt` (whose `SPAN` regex already extracts
"before ..." and whose lead-drop set also lacks it), so there is no code change, only a pinned test, a
comment, and four rows in `date_norm.json` (`before Wednesday`, `before tomorrow`, `before next Friday`,
`before the 21st` -> null). The Kotlin test was not run (no Gradle in this pass); its set is read-identical.
