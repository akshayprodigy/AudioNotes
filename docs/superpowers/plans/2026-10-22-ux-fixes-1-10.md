## Task 1 — The import link must be reachable on the Record screen (finding 1, BLOCKER)

**Problem.** `src/screens/RecordScreen.tsx`: the idle "Or import a recording ›" link (added in
1.1.4, near `AllowanceLine`, ~line 652–668) sits inside the short `ScrollView` (`st.variable`)
between the mode switch and the clock. On first use the `FirstRecordingNote` card plus the mascot
fill that box, so the allowance line and the link are clipped out of view on a 720×1600 phone.

**Change.** Move the "Or import a recording ›" link OUT of that ScrollView to the footer under
the mic button — the row that today reads "Stays on this device. Show the room". The footer keeps
that line, and the import link sits on its own line beneath it (centred, same `chip` style,
`primaryDeep`), shown only when idle (`!isRecording`) and not spent (`!spent`), exactly the
conditions it has today. Its `accessibilityLabel` stays "Import a recording" and it still calls
`navigation.navigate('Library', { importNow: Date.now() })`. Leave the AllowanceLine where it is.

**Acceptance.**
- The existing tests in `RecordScreen.allowance.test.tsx` for the link still pass unchanged (the
  link found by its label, pressing it navigates with `importNow`; no link when spent).
- New test: the link is NOT a descendant of the ScrollView that holds the AllowanceLine
  (find the `ScrollView` instance(s) and assert none contains a node labelled "Import a recording").
- Mutant: move the link back inside the ScrollView → the new test fails.

## Task 2 — No battery dialog at first launch; ask at the first recording, with a reason (finding 2)

**Problem.** `src/setup/essentialDownload.ts:75` calls `AudioPipeline.requestBatteryExemption()`
at the start of every essential download run, which on a fresh install is the moment the app
opens: Android's "Let app always run in background?" appears before the person has seen anything.

**Change.**
1. Remove the call from `runDownloads` in `essentialDownload.ts` (leave its comment's intent in a
   one-line note that the exemption is now asked at the first recording).
2. In the Record screen's start-recording path (`src/screens/RecordScreen.tsx`, where the mic and
   notification permissions are requested before a recording starts), the FIRST time a recording
   is started on this install, show a platform `Alert` before the system dialog:
   title `Keep recording with the screen off`, body
   `Android may stop long recordings and note-writing when the screen is off. On the next screen, tap Allow so Verbale can keep going.`,
   one button `Continue` whose press calls `AudioPipeline.requestBatteryExemption()` and then
   continues starting the recording. Remember it was asked with the setting key
   `battery_exemption_asked` = `'1'` (via `db.setSetting`/`db.getSetting`, the same store the
   screen already uses), so it is asked once per install.
3. `src/setup/proModels.ts` keeps its own call (it happens right after a purchase, in context).

**Acceptance.**
- `essentialDownload` test: a run does NOT call `requestBatteryExemption` (add it to
  `src/setup/__tests__/essentialDownload.test.ts`).
- Record test (in `RecordScreen.allowance.test.tsx` or `RecordScreen.setup.test.tsx`, whichever
  already drives a start): on the first start with `battery_exemption_asked` unset, the Alert
  appears with that title; pressing Continue calls `requestBatteryExemption` and stores the key;
  with the key already `'1'`, no Alert and no call.
- Mutant: skip the `getSetting` check (always ask) → the "already asked" test fails.

## Task 3 — First run: the welcome stays readable; the download says it carries on (finding 3)

**Problem.** `src/screens/OnboardingScreen.tsx`: because the first-run download auto-starts, the
welcome content is replaced immediately by the "Preparing your app" view (~line 255–290), so the
welcome is never read. Its sub-line says "Keep the app open", which contradicts the background
download.

**Change.**
1. While the essential download is running, keep rendering the welcome content (hero, the feature
   cards) and show the download's progress as a compact block (the same progress bar, the model's
   purpose and its "N MB of M MB" label) in place of the welcome's primary button, instead of
   replacing the whole screen. Read the code first; if the "Preparing" view is also used for other
   states (failed, paused, done), keep those states working — only the "running, first time" case
   changes.
2. Change the sub-line `Setting up the on-device speech models, one time only. Keep the app open; recording works offline after this.`
   to `Setting up the on-device speech models, one time only. It carries on if you leave the app; recording works offline after this.`

**Acceptance.**
- An onboarding test (in `src/screens/__tests__/OnboardingScreen.test.tsx`) with a running
  download asserts the welcome's title/feature text AND the progress are both rendered.
- No test anywhere still expects "Keep the app open".
- Mutant: restore the full-screen replacement for the running case → the new test fails.
- If this cannot be done without restructuring the screen beyond ~80 changed lines, STOP and
  report BLOCKED with what you found.

## Task 5 — Meeting tabs: Free Summary leads with the meeting, not an advert; no duplicate headline; no transcript pencils (findings 5, 6, 7)

**Problems.**
- `src/screens/meeting/SummaryTab.tsx` ~546: on Free (no written summary) the Summary card's body
  is the Pro pitch ("The minutes below were pulled out… Pro writes…") with a big Get Pro button.
- `src/screens/meeting/MinutesTab.tsx`: a big takeaway headline ("Decided: …", from
  `takeaway.ts`) repeats the first item of the Decisions card right below it.
- `src/screens/meeting/shared.tsx` ~686: every transcript line draws a pencil button, although
  long-press already corrects a line (its hint says so).

**Change.**
1. Free Summary card: lead with the meeting itself — the takeaway line from `takeawayOf` (the
   same function MinutesTab uses) as the card's body. Under it, one small line
   `Pro writes the whole meeting up in plain English.` with the existing upgrade action as a small
   text link `Get Pro ›` (not the large button). If `takeawayOf` returns nothing, show
   `The minutes below were pulled out of what was said.` instead. Pro's written summary is
   unchanged.
2. MinutesTab: remove the takeaway headline when the Decisions card is shown (its first item is
   the same sentence). Keep it when there are no decisions (then it is "Next: …" and not a repeat).
3. Transcript lines: remove the per-line pencil. Long-press correction and its accessibility hint
   stay. Keep the "Tap a line to hear it. Long press to correct it…" hint line.

**Acceptance.**
- SummaryTab test (Free, rule-based meeting with a decision): renders the takeaway text, renders
  "Get Pro ›", does not render the sentence beginning "The minutes below were pulled out" when a
  takeaway exists.
- MinutesTab test: with decisions, no "Decided: …" headline above the card; with no decisions, the
  "Next: …" line still shows.
- Transcript test: no line renders an edit/pencil button; long-press still opens correction.
- Mutants: (a) bring the Pro pitch back as the Free body → SummaryTab test fails; (b) always render
  the headline → MinutesTab test fails.
