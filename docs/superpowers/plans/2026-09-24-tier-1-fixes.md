# Tier 1 fixes — the plan and the to-do list

*24 September 2026. From the four-area UX audit run the same day; every item below was checked
against the code before it went on this list. Founder's decision: all ten Tier 1 items before
launch, in two development phases, Phase A first.*

Each phase is built by Sonnet from an execution sheet, reviewed by Opus against the code, then
checked by hand by the founder. Tick an item only when its phase is reviewed AND checked on a phone.

## Phase A — buying works, and the app always knows you are Pro

Sheet: `docs/superpowers/specs/2026-09-24-phase-a-buying-and-pro-state-execution.md`
(two builder sessions: A1 server + billing logic, A2 screens).

- [ ] **A1. "Subscribe" in Settings can buy.** It called Play without naming a plan, which Play
  refuses when there are two. It now opens the Pro screen (plans, trial, terms). *(audit item 1)*
- [ ] **A2. A payment that went through is never reported as failed.** Server unreachable or
  down → "Payment received — Pro switches on by itself"; a payment still authorising →
  "Payment still processing". *(audit item 2)*
- [ ] **A3. Pro is checked on every launch AND every return to the app**, and a purchase the app
  never heard back about (offline at purchase, slow UPI payment) is picked up then — not only when
  Settings is opened. *(audit items 2, 3)*
- [ ] **A4. A lapsed or unconfirmed subscriber has somewhere to go.** "Check again" and "Manage in
  Google Play" wherever "Pro is off" is shown; Restore on the Pro screen; Manage in Settings for
  everyone on a Play install; the lapsed sentence no longer claims the subscription ended when the
  phone merely could not check. *(audit item 3)*
- [ ] **A5. Buying Pro is noticed straight away** by the Library (Search/Actions/Threads) and
  Settings, not after a restart. *(audit item 4)*
- [ ] **A6. Reinstalling can never lock a paying customer out.** The device id lives in the app's
  storage, so every reinstall or "clear data" was a new device and the third one hit the 3-device
  wall for good. At the limit, the device used least recently now makes room. *(found while
  planning A3; server change + deploy)*

## Phase B — nothing is lost, and nothing false is said

Sheet: to be written after Phase A's review (anchors are grepped on the day of writing).

- [ ] **B1. "Write it again" and changing the meeting type keep the old summary** until the new
  one exists (the safe `force` path is built; the screen does not use it). Type change asks
  first. *(audit item 5)*
- [ ] **B2. Every ending is processed and explained.** Free limit, mic lost, disk full: the
  meeting is sent for processing at once (today only Stop does it), the reason is saved on the
  meeting and shown, and a notification says what happened. *(audit item 6)*
- [ ] **B3. A crash is not "no speech".** Its own status, a plain-language reason, a visible
  Retry, and the automatic sweep retries it. *(audit item 7)*
- [ ] **B4. An announcement nobody heard is reported** — on the record screen, in the
  notification, and on the meeting ("announced" / "not announced"). *(audit item 8)*
- [ ] **B5. A meeting that is queued, paused or waiting for a model never reads "could not hear
  any speech".** *(audit item 9)*
- [ ] **B6. Merging speakers asks first** ("Merge Speaker 3 into Speaker 1?") naming both.
  *(audit item 10)*
